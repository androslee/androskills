# Coordination ladder: seven patterns

The model ladder specifies *which* models/providers work and in what order. This separate ladder describes *how* agents coordinate on work. Pick a pattern for the task, model capabilities and actual host; a higher position is not automatically better, and there is no requirement to progress through the seven. A model stage can use a compatible pattern without changing the user's provider order or increasing its authorized budget. The host's permissions, available tools and user constraints always win.

1. **One agent:** Give one agent the desired outcome, constraints, available tools and a way to verify success. Let it work through the task and appropriate checks. Prefer this for cohesive, coupled work where extra coordination brings little value.
2. **Fan-out:** Delegate genuinely independent investigations or tasks to bounded workers and integrate their results. Define scopes and expected outputs; don't assume pieces are independent merely because a specification can be divided into tickets. Use separate workspaces or non-overlapping ownership when available. Fall back to the authorized non-parallel workflow when the host cannot delegate.
3. **Effort scaling:** Route a self-contained easy task to an approved cheaper model, or ask an approved stronger advisor for a narrow difficult problem. Continue with the existing builder when possible and verify advice against the artifact. Only use model choices and cloud sharing the user has authorized; do not silently change providers, multiply calls or treat a role-played advisor as a model invocation.
4. **Pairs:** A builder produces an artifact; a reviewer checks it and sends specific, evidence-backed findings back to the same builder if the host can resume it. Repeat only while it is useful. A separate verifier can exercise the required behavior and return failures to that builder. Where no independent agent is available, be transparent about same-context review; provide a handoff for a required unavailable reviewer. By default all feedback and fix cycles stay within the current model rung's three-pass limit, including its initial pass; do not reset that limit per agent. The user or host may set stricter limits. Keep verification proportional to the task and honor required checks.
5. **Manager thread:** When the host actually supports persistent threads and messaging, one coordinator tracks a shared goal, assigns distinct work, records status and dependencies, integrates results and reports to the user. Bound workers and tool calls, use explicit ownership, and preserve user control. A skill alone does not create persistent conversations or a message bus.
6. **Long-lived leads:** Experimental. Persistent leads with distinct responsibilities may coordinate workers over multiple sessions. Use only when specifically requested, the host supports real persistence and boundaries, and the user has authorized its resource and privacy costs. Establish a shared objective, ownership, explicit stopping conditions, a durable work record and conflict resolution; periodically check whether useful work justifies coordination overhead. Do not pretend that transient subagent calls are durable leads.
7. **Agent swarms:** Experimental and resource intensive. Large groups explore many independent approaches and share findings. Use only with explicit user authorization, actual host capacity, effective resource controls and a suitable decomposable task. Define an overall budget, participant limits, coordination and stopping rules, and a human-visible review path. Avoid escalating to a swarm by default; models can duplicate work, converge on the same mistakes or interfere with one another. If prerequisites are absent, explain and use a permitted smaller pattern rather than simulating a swarm.

## Selection and evidence

Start with the user's goal and acceptance criteria, assess whether the work is coupled, the expected benefit of independent evidence, model/provider availability, privacy, cost and host limits. Preserve the user's preference to do as much useful work as possible at each selected model stage. For a blocker, an authorized stronger advisor can help the current builder without automatically abandoning that stage. For parallel review or implementation, also follow [multiagent.md](multiagent.md) for evidence, handoffs and conflict safeguards. Do not claim a pattern, model or independent check ran unless the host actually ran it.

The seven names above follow the presenter’s summary in [OpenAI Revealed What Comes After Loops, around 1:14](https://www.youtube.com/watch?v=yrRpnx_iugY&t=74s), where the video attributes the ladder to an OpenAI talk. This reference describes the video’s presentation; it is not a claim that the original talk or this skill has independently validated every level. The video also distinguishes established tool-like delegation from experimental long-lived peers and swarms. Anthropic's [multi-agent research](https://www.anthropic.com/research/multiagent-systems) documents coordination failures and warns against assuming agent agreement or a larger group is reliable.
