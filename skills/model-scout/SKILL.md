# Model scout

Recommend models for the user's actual task and constraints, including local-first or inexpensive Ladder stages. This skill advises; it does not change providers, models, settings, install software, or send private data to outside services. Never claim access, pricing or benchmark results that have not been verified.

1. Establish task type and success criteria, important capabilities (such as vision, context and tools), latency, privacy, budget and the available provider/model list. Inspect model catalogs and local configuration only through permitted read-only tools; avoid secrets, chat contents and unrelated data. Availability in a catalog is not proof of entitlement, working credentials or runtime capacity. Ask the user when essential information cannot be determined; distinguish confirmed access from listed or assumed access.
2. When network access is permitted, consult current [Artificial Analysis](https://artificialanalysis.ai/models/) and the relevant [Arena leaderboard](https://arena.ai/leaderboard), plus actual provider/model documentation for availability and prices. Send only generic public model names in external queries; do not upload private inventory, account information, prompts or artifacts without authorization. Record retrieval date, source links, exact model/version and relevant configuration. Never invent missing entries; say when a page is inaccessible or a comparison is unavailable. Offline, use dated cached or user-supplied evidence and label it; do not present it as current.
3. Match exact model version, provider, reasoning effort and endpoint when evidence permits. Flag mismatches: public benchmarks for a hosted full-precision model may not represent a local quantization, a different effort setting, provider or harness. Arena preference, coding and agent leaderboards measure different things; note category, votes and uncertainty when available. Artificial Analysis scores, task costs and blended token prices follow their own methodology; do not treat them as Arena preference scores, universal quality or directly comparable numbers.
4. Estimate costs using the user's actual provider prices and expected input, cached input and output/reasoning tokens, where available; disclose assumptions, pricing units and uncertainty. Subscription allowances, rate limits, free tiers, tool costs and local hardware/electricity or opportunity cost can change the result. Local inference is not automatically free; avoid inventing a dollar estimate. Compare expected cost per successful task, not merely per token, where evidence supports it.
5. Present a compact comparison with exact models, confirmed access, relevant capabilities, evidence and limitations, plus a proposed choice for each requested role. Explain meaningful quality, speed, privacy and cost tradeoffs and suggest a small representative local evaluation when rankings don't predict the task. Do not claim human preference is task success. Ask before changing a saved Ladder profile or selecting an unapproved provider. Preserve user choices and report unavailable evidence or tools.

Methods: [Artificial Analysis methodology](https://artificialanalysis.ai/methodology); [Arena ranking guidance](https://help.arena.ai/articles/7011479247-how-to-see-ai-rankings-in-arena-leaderboards-2-0-wip).
